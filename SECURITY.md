# Security

Do not post credentials, authentication cookies or sensitive account data in public issues. Use the repository's private vulnerability reporting feature if it is available, or privately contact the repository owner before disclosing an exploitable vulnerability.

Security boundaries include exact editor/design identity checks, single-use publication approval, explicit website-terms consent, DOM uniqueness checks, local hash-based duplicate prevention and holds on uncertain submission outcomes. These checks do not replace review of the artwork, listing or website terms.

The current project is experimental. Historical tests do not guarantee compatibility with the current TeePublic site.
